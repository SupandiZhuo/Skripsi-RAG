# Authorized research input contract

This is a collection checklist. It intentionally contains **no purported company dataset or expert answers**.

## Asset profile

Keep a stable `asset_id` shared by the asset table, installed software and context documents. Supply business function, environment, internet exposure, network zone, business criticality, data sensitivity/classification and operational consequences. Do not use a person's name or contact details when a role suffices.

Provenance should include source ID/type/version, collection date, verifier role/time and an explicit synthetic flag. Missing or unverifiable values stay `unknown`. Do not copy hidden expert CR/IR/AR into raw-context fields.

## Installed software

One asset may have several records. Recommended CSV header:

```text
asset_id,software_id,vendor,product,version,cpe,source_id,last_verified,inventory_verified
```

Validate the complete CPE 2.3 formatted string, including escaped separators. A verified primary product is not proof that the whole inventory is complete. Mark an asset's inventory verified only after checking supporting platforms and relevant components. Preserve exact observed version strings; unsupported vendor comparison schemes remain Unknown.

## Context JSONL

Use one JSON object per authorized evidence chunk with:

- `document_id`: stable globally unique document/chunk identifier;
- `asset_id`: exact target asset identifier;
- `source_id`, `source_type`, `source_version`: traceable sanitized source;
- `source`, `source_reference`: non-empty sanitized source name and reference;
- `last_updated`: exact ISO calendar date (`YYYY-MM-DD`), required by ingestion;
- `collected_at`: ISO-8601 date or timestamp;
- `verified_by_role`: anonymous verifier role;
- `is_synthetic`: explicit JSON boolean;
- `content`: sanitized source text, not instructions or expert labels.

Ingestion requires `asset_id`, `document_id`, `source_id`, `source`,
`source_reference`, `last_updated`, `is_synthetic` and `content`. Additional
provenance fields are retained; absent collection/verification/version facts
are explicitly stored as `unknown`, not inferred as verified. Chunk IDs and
content-integrity values are generated by ingestion, not authored by experts.

Validate before writing the collection:

```bash
python ingest_assets.py --context-jsonl /path/to/approved-context.jsonl --validate-only
python ingest_assets.py --context-jsonl /path/to/approved-context.jsonl
```

Do not put `.env` files, credentials, private keys, personal contacts or raw internal IP inventories in context text. Review both text and metadata: stripping metadata fields does not sanitize secrets copied into prose. Retain source permissions separately from the vector index.

## Scenario and reference separation

Each experiment scenario needs a unique scenario ID, CVE ID, asset ID and frozen NVD snapshot. Expert annotations must be a separate file with anonymous rater IDs, applicability, CR/IR/AR, priority, supporting evidence IDs, rationale and annotation time. Retrieval labels separately identify the document IDs relevant to each query/asset pair. Label files must never be ingested into model context.

Do not manufacture sample labels to fill these contracts. Unit-test fixtures are explicitly synthetic and cannot serve as thesis ground truth.
